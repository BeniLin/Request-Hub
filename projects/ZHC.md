## 測試

自動化測試一律從環境變數取得網址與帳號，不可寫死：

| 環境變數 | 內容 |
|---|---|
| `E2E_BASE_URL` | 前台網址（對外網站） |
| `E2E_ADMIN_URL` | 後端網址。後台 `/admin/` 只能從這個網址進入，前台網址看不到後台 |
| `E2E_ADMIN_USER`、`E2E_ADMIN_PASSWORD` | 後台管理者的帳號密碼 |

執行環境的前提：

- 驗證環境的資料不會在每次執行前清空。測試需要的資料要自己建立，名稱加上不會重複的字串（例如時間），不可以假設環境中沒有其他資料
- 測試從 `tests/e2e/` 以 `npx playwright test <單號>/` 執行
- 設定檔必須讓每個測試結束時都保留截圖
- 不可以修改全系統共用的設定（例如相簿與檔案的系統設定）。需要特定的類型或大小限制時，用測試自己建立的資料（例如上傳連結本身的限制）達成；做不到的 Test Case 列為人工驗證

### 測試帳號

- **預設一律使用 `E2E_ADMIN_USER`**（最高管理者）。只有 Test Case 要驗證權限差異（有某權限的人可以做、沒有的人不能做）時，才使用其他測試帳號
- 需要其他帳號時，規格的 Test Case 段落要有「測試帳號」表，每個帳號寫出：代號、環境變數、需要的權限、**不能有**的權限、要加入的帳號群組（決定看得到哪些資料夾或專案）
- 環境變數命名為 `E2E_USER_<代號>`、`E2E_PASSWORD_<代號>`，代號用英文大寫與底線，例如 `E2E_USER_ALBUM_VIEWER`。權限組合相同的帳號跨單共用同一個代號，撰寫前先查其他單的 `tests/e2e/*/README.md` 是否已經有
- 測試不可以自己建立帳號或修改帳號的權限
- **執行前檢查**：使用其他測試帳號的單，在該單所有測試開始前先檢查每個帳號：環境變數存在、可以登入、需要的權限都有（打開需要該權限的頁面看得到）、不能有的權限確實沒有（打開會被拒絕）。任一項不符合就停止這張單的全部測試，不往下執行，錯誤訊息以「【測試環境缺少帳號】」開頭，逐一列出缺少或不符合的帳號代號、環境變數名稱、需要與不能有的權限、帳號群組
- 這類失敗不是程式的問題，不要修改程式碼。看到「【測試環境缺少帳號】」時轉為 `D 待人工處理`，由人建立帳號、設定環境變數後再重新驗證
