# B 關卡：確認規格與 Test Case

這是成本最低的攔截點。規格錯了，後面的實作、測試、審查全部白做。

## 要讀的東西

1. Jira 單的描述與備註（原始需求，以及任何【需求變更】）
2. 分支上被新增或修改的規格文件（從步驟 3 寫入的 Jira 備註找檔案清單）
3. 分支上的 Test Case
4. 原本 main 上的同一份規格（比對改了什麼）

## 檢查項目

### 需求覆蓋
- 每一條驗收條件（AC）都有對應的 Test Case
- 每個 Test Case 都對應得回某條 AC，沒有多出需求以外的東西
- 【需求變更】備註的內容都有反映進去

### Test Case 品質
- 預期結果是具體可驗證的（數字、狀態、畫面元素），不是「正確顯示」這種描述
- 有涵蓋邊界值（剛好等於門檻、零、最大值）
- 有涵蓋需求中列出的例外與錯誤處理
- 預期畫面與需求中的畫面描述一致
- 每條 Test Case 都能被自動化執行：步驟、輸入資料、預期結果都明確，沒有「視情況」「適當地」這類需要人判斷的描述。通過後下一步是 AI 把它們轉成測試腳本，寫不清楚的會被退回

### 規格文件
- 「不做的範圍」沒有被寫進規格
- 修改既有規格時，沒有意外刪除或改變不相關的規則
- 與其他規格文件沒有互相矛盾
- `INDEX.md` 有同步更新

## 常見問題

- AI 自行補上需求沒提到的規則（例如自己決定錯誤訊息的文字），這類要特別標出來讓使用者確認
- Test Case 只測成功情境
