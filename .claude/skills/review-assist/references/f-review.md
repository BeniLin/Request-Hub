# F 關卡：畫面確認與 Code Review

**畫面由使用者自己看**：截圖附在 Jira 單上，請使用者對照預期畫面確認。你負責程式碼和驗證結果。

## 要讀的東西

1. Jira 單的描述、備註（含步驟 5 的修改說明、步驟 7 的驗證結果）
2. PR 資訊：`view`、`files`、`checks`
3. PR 的 diff（檔案很多時，先看 `files` 清單，挑重點檔案說明）

## 檢查項目

### 範圍
- 修改的檔案都跟這個需求有關，沒有順手改了不相關的東西
- 沒有實作「不做的範圍」中的內容
- `specs/` 沒有被修改（實作階段不應修改規格，若有修改是嚴重問題）

### 正確性
- 實作邏輯符合驗收條件
- 例外與錯誤處理有實作，不是只處理成功情境
- 驗證結果全部 Pass，CI 檢查全部通過

### 安全
- 沒有寫死的密碼、金鑰、token
- 使用者輸入有經過驗證
- 權限檢查有實作（需求中「不應該能使用的角色」確實被擋下）

### 可維護性
- 沒有大段複製貼上的重複程式碼
- 新增的測試真的有在驗證行為，不是只為了讓覆蓋率好看

## 回報時要特別說明

- diff 很大時，說明你看了哪些、沒看哪些，不要讓使用者以為你全部看過
- 你無法判斷的業務邏輯，放在「建議確認的地方」
