# 建立 Jira 單

建出來的單是步驟 3 自動化的唯一輸入，格式必須固定。n8n 在步驟 3 開頭會檢查必要欄位，缺漏會被退回。

## 前置條件

開始前確認：

- 有使用者確認過的需求摘要
- 有使用者確認過的拆單計畫
- 摘要裡沒有未回答的「假設」

缺任何一項，回到對應的 skill，不要直接建單。

## 流程

### 1. 查重

對每張要建的主單，用 Jira 搜尋未完成的單子：

```
project in (<涉及的專案KEY>) AND statusCategory != Done AND text ~ "<關鍵字>"
```

用 2 到 3 組不同關鍵字各搜一次。找到相似的單子時，列給使用者看（單號、標題、狀態），問他要：

- 繼續建新單
- 改成在既有的單子補充（這時改用 `ticket-followup`，不要建新單）
- 放棄

### 2. 讀取專案設定

讀取 `projects/<KEY>.md` 的「Jira 設定」，取得議題類型名稱、元件、標籤等設定值。不要自己猜欄位名稱。

### 3. 組合內容並預覽

- 主單描述使用 `templates/story.md`
- Subtask 描述使用 `templates/subtask.md`

把**所有要建立的單子完整內容**一次顯示給使用者預覽，包含標題、議題類型、元件、標籤、描述，以及相依關係。

問使用者：「確認後我會依序建立以上 N 張單，可以嗎？」

### 4. 建立

使用者確認後依序建立：

1. 主單
2. 主單的 subtask（parent 設為該主單）
3. 主單之間的相依連結（Blocks）

建立後系統會再跳出確認視窗，這是正常的，請使用者確認即可。

**不要轉換狀態。** 新建的單會自動是 A（待撰寫規格）。建立後檢查狀態，如果不是「待撰寫規格」，告訴使用者並請他通知 Jira 管理員檢查 workflow，不要自己去轉換。

### 5. 回報結果

列出所有建立的單號與連結，並提醒：「單子已進入 A 狀態，自動化流程會接手撰寫規格，完成後會進入 B 狀態等待確認。」

## 標題規則

- 主單：`[<KEY>] <動詞開頭的一句話>`，例如 `[SHOP] 金卡會員結帳自動套用折扣`
- Subtask：`<動詞開頭的一句話>`，不加前綴

## 失敗處理

建單途中失敗時，列出哪些已建立、哪些沒有，不要自行重試整批（會造成重複的單子）。只重試失敗的那一張，並先確認它確實沒有被建立。
