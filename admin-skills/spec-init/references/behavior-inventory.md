# 行為清單指南（階段 3 使用）

目的：把一個領域裡「會發生的事」全部列出來，再逐項追蹤。先列清單再分析，才知道還有多少沒看。

原則：**搜尋用來找線索，完整讀檔用來確認沒有遺漏。** 屬於這個領域的每個檔案都要從頭讀到尾。

## 1. 找出屬於這個領域的檔案

從階段 1 記錄的程式碼位置開始，再往外找：

- 前端：頁面、元件、樣板、該頁載入的腳本與共用片段（include、partial、layout 中與這個領域有關的部分）
- 後端：路由、服務、資料模型、驗證、權限、共用的裝飾器或中介層
- 資料：migration、初始資料、資料表定義
- 測試：單元測試、整合測試、前端測試
- 設定：會改變行為的設定值與環境變數（只記名稱與作用，不記內容）

共用元件（確認視窗、下拉選單、上傳元件等）被多個領域使用時，在第一個用到的領域完整記錄，其他領域註明參照。

## 2. 前端操作

每個頁面、元件、樣板完整讀過，登記使用者能做的每個動作。以下搜尋詞只是起點，依專案的技術調整。

| 類型 | 要找的東西 | 搜尋線索 |
|---|---|---|
| 點擊 | 按鈕、連結、圖示、可點的列或卡片、分頁標籤、展開收合 | `@click`、`onClick`、`onclick=`、`addEventListener('click'`、`.on('click'`、`<a href`、`<button`、`role="button"` |
| 雙擊、右鍵、長按 | | `dblclick`、`contextmenu`、`touchstart`、`pointerdown` |
| 拖拉 | 排序、移動、拖檔案上傳、調整大小 | `draggable`、`dragstart`、`dragover`、`drop`、`Sortable`、`dnd`、`pointermove`、`resize` |
| 鍵盤 | 快速鍵、Enter 送出、Esc 取消、方向鍵選取、Tab 順序 | `keydown`、`keyup`、`keypress`、`@keydown`、`onKeyDown`、`accesskey`、`hotkey`、`shortcut`、`event.key`、`ctrlKey`、`metaKey` |
| 輸入與選取 | 文字欄位、下拉、勾選、日期、搜尋框、即時篩選 | `v-model`、`@input`、`@change`、`onChange`、`<input`、`<select`、`<textarea`、`debounce` |
| 表單送出 | | `<form`、`@submit`、`onSubmit`、`type="submit"`、`formaction` |
| 檔案 | 選檔、拖檔、貼上圖片、下載 | `type="file"`、`FileReader`、`paste`、`download`、`Blob` |
| 剪貼簿 | 複製連結、貼上 | `clipboard`、`execCommand('copy'` |
| 捲動與顯示 | 無限捲動、捲到才載入 | `scroll`、`IntersectionObserver` |
| 瀏覽器行為 | 上一頁、重新整理、離開前確認、網址參數 | `popstate`、`history.`、`beforeunload`、`router.`、`location.`、`URLSearchParams` |
| 記在瀏覽器的狀態 | 記住的篩選、主題、收合狀態 | `localStorage`、`sessionStorage`、`cookie` |
| 不需要使用者動作 | 載入時抓資料、定時更新、收到推播後更新 | `onMounted`、`useEffect`、`DOMContentLoaded`、`setInterval`、`setTimeout`、`WebSocket`、`EventSource`、`mqtt`、`watch` |

搜尋找不到、只能靠讀檔發現的情況：

- 事件委派：監聽掛在外層，用 `data-*` 屬性或 class 決定做什麼
- 動態產生的元素與由設定檔產生的選單
- 共用元件內部的行為（確認視窗的 Esc、預設焦點）
- 由 CSS 控制的顯示與隱藏（`:hover`、`disabled`、媒體查詢）
- 伺服器端樣板中依權限或狀態才輸出的按鈕

每個操作登記：所在頁面、元素、操作方式、出現的條件、位置。

## 3. 前端送出的請求

| 要找的東西 | 搜尋線索 |
|---|---|
| API 呼叫 | `fetch(`、`axios`、`$.ajax`、`XMLHttpRequest`、`sendBeacon`、專案自己包的請求函式 |
| 表單與連結直接送出 | `<form action`、`method="post"`、`<a href` 指向會改資料的網址 |
| 即時連線 | `WebSocket`、`EventSource`、MQTT 訂閱的主題 |

每個請求記錄：方法、路徑、帶的資料、由哪個操作觸發。

## 4. 後端入口

| 類型 | 搜尋線索 |
|---|---|
| 路由 | 見 `survey-guide.md` 第 2 節。同時找用程式註冊的路由（`add_url_rule`、迴圈註冊、藍圖前綴） |
| 每個請求都會經過的程式 | `before_request`、`after_request`、middleware、filter、interceptor、裝飾器 |
| 排程與背景工作 | `cron`、`schedule`、`@Scheduled`、`celery`、`queue`、`worker`、`job`、`thread`、CI 設定檔中的定時工作 |
| 外部呼叫進來的 | `webhook`、`callback`、訊息佇列的訂閱 |
| 啟動時執行 | 應用程式初始化、載入快取、建立預設資料 |
| 指令 | CLI 指令、管理腳本 |
| 事件與掛鉤 | ORM 的事件監聽、signal、觸發器 |

每個入口記錄：誰可以呼叫（登入、權限、金鑰）、檢查的項目與順序、成功的回應、每一種失敗的回應。

用文字比對算出的數量只是線索。**以完整讀過路由檔後列出的清單為準**。

## 5. 資料寫入與其他結果

| 類型 | 搜尋線索 |
|---|---|
| ORM 寫入 | `session.add`、`session.delete`、`session.merge`、`commit`、`flush`、`bulk_`、`.save(`、`.create(`、`.update(`、`.delete(`、`.destroy(` |
| 直接下 SQL | `INSERT`、`UPDATE`、`DELETE`、`TRUNCATE`、`execute(` |
| 資料表自己的行為 | 預設值、自動更新的時間欄位、唯一限制、外鍵的連動刪除、觸發器 |
| 檔案 | 寫檔、搬移、刪除、產生縮圖或報表 |
| 快取 | 寫入與清除快取的程式 |
| 對外 | 呼叫外部 API、發訊息、寄信、發布事件 |
| 紀錄 | 操作紀錄、稽核紀錄（一般除錯日誌不用記） |

每處寫入記錄：哪個資料表、新增／修改／刪除、哪些欄位、值從哪裡來、由哪些入口觸發、是否和其他寫入在同一個交易中、失敗時已寫入的部分會怎樣。

真刪除與軟刪除要分清楚。寫入資料庫成功、但後續步驟（寫檔、更新快取、通知）失敗時的結果要特別記錄。

## 6. 情境檢查表

對每個功能逐類檢查。每一類都要有結論：目前的行為、不適用（寫原因）、或程式碼沒有處理（列為未確認事項）。

| 類別 | 要檢查的情境 |
|---|---|
| 身分與權限 | 沒登入；登入但沒有權限；有部分權限；操作別人的資料；直接輸入網址或直接呼叫 API 繞過畫面；登入逾時後送出 |
| 輸入 | 必填沒填；空白字串與只有空格；超過長度；格式錯誤；特殊字元、表情符號、HTML 標籤；數值的 0、負數、小數、極大值；日期的過去、未來、跨日、跨月、跨年、時區；重複的值 |
| 資料狀態 | 目標不存在；已被刪除；已停用；每個狀態下可不可以做這個操作；被其他資料參照時能不能刪 |
| 重複與同時 | 連按兩次；重新整理後重送；兩個人同時修改同一筆；處理到一半再操作一次 |
| 資料量 | 沒有資料時畫面顯示什麼；只有一筆；很多筆時的分頁、排序、上限 |
| 檔案 | 大小上限；不允許的類型；同名檔案；空檔案；檔名有特殊字元；上傳中斷 |
| 外部系統 | 逾時；回傳錯誤；回傳非預期的內容；完全連不上；設定沒填 |
| 部分失敗 | 多個步驟中間失敗時，前面的結果會不會回復；批次處理中某一筆失敗時其他筆怎麼辦 |
| 畫面操作方式 | 只用鍵盤能不能完成；Enter 與 Esc 的行為；預設焦點在哪；取消與關閉視窗；拖到不能放的位置；手機寬度；上一頁與重新整理後的狀態 |
| 一致性 | 存檔後其他頁面、快取、前台多久看得到；刪除後相關的地方怎麼顯示 |
| 時間 | 排程的執行時間與漏跑時的處理；到期與過期；時區與日光節約時間 |

系統有這份表沒列到的特性時（多語系、金額計算、多租戶等），自行加上對應的類別並告知使用者。

這份檢查表能減少遺漏，但不能保證涵蓋所有情況。報告時說明檢查了哪些類別，不要寫「已涵蓋所有情況」。

## 7. 追蹤時的記錄方式

一個操作一條線，從畫面追到資料：

```
A-12 聚會列表頁，按「刪除」
  條件：有「管理聚會」權限才看得到按鈕
  畫面：跳出確認視窗，焦點在「取消」；Esc 或點背景取消
  請求：POST /admin/meetings/<id>/delete   → E-7
  檢查：登入 → 權限 → 聚會存在 → 沒有已產生的週報
  寫入：D-15 meetings 刪除一筆；D-16 連帶刪除 meeting_items
  連帶：更新快取、發布事件
  回應：成功 → 列表移除該列並顯示「已刪除」；失敗 → 顯示錯誤訊息，列表不變
  情境：沒權限 → 403；不存在 → 404；有週報 → 拒絕並說明原因
  驗證：程式碼（或 測試：<測試名稱>；或 實測：<日期>）
```

（以上只是格式示範，不是任何專案的實際行為。）
